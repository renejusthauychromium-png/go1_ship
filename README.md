# Unitree Go1：揺れる甲板の上を60秒、転倒せずに歩く（v6）

公開されている四脚歩行方策 **WTW（Walk These Ways）** を、物理シミュレータ **MuJoCo（MJX）** 上のUnitree Go1に載せ、
船の甲板のように揺れる床（ロール・ピッチ・上下動）の上を一定速度で60秒歩かせます。
WTWの重みは変えずに、WTWが出力する関節の目標角に小さな補正（±0.12 rad以内）を足す**補正モデル**を、
強化学習 **PPO（Proximal Policy Optimization）** で学習します。

## 2つのノートブック
| ファイル | 版 | 内容 |
|---|---|---|
| `unitree_go1_multispeed.ipynb` | **v0**（最初のノートブック） | 指令速度0.10〜0.30 m/sで補正モデルを学習します。`trained/v0_policy.pkl` はこのノートブックで作成したモデルです |
| `unitree_go1_ship_v6.ipynb` | **v6**（提出版） | 指令速度0.15 m/s以上ではv0のモデルをそのまま使い、0.15 m/s未満では**低速専用モデル**（v0から0.10〜0.15 m/sだけで追加学習）に切り替えます（ゲインスケジューリング）。評価・静止甲板の対照・比較動画まで行います |

どちらのノートブックも、必要なPythonコードを `%%writefile` セルで書き出すため、ほかのソースファイルは不要です。

## 評価の条件
- 波 **seed 1000〜1004** × 指令速度 **0.10／0.20／0.30 m/s** の15条件、各60秒、途中リセットなし（v0と同じ手順）
- 評価用の波（seed 1000〜1004）は、学習にもモデルの選択にも使っていません。学習には10000番以上、低速専用モデルの選択には5000番台と7000番台の波を使います

### 作り方（どちらもこのリポジトリのノートブックだけで作れます。ほかのノートブックは不要です）
1. **`v0_policy.pkl`**：`unitree_go1_multispeed.ipynb` を実行すると、
   `マイドライブ/ship_robot_runs/experiment04_multispeed/level_04/policy.pkl` に保存されます。これを `v0_policy.pkl` という名前で同梱しています。
2. **`low_speed_specialist.pkl`**：`unitree_go1_ship_v6.ipynb` の設定セルで `TRAIN_SPECIALIST = True` にして実行したときの、
   「6」の手順2・3（低速専用モデルの学習と選択）で作られます。具体的には次のとおりです。
   - 1のv0モデルを出発点に、指令速度0.10〜0.15 m/sだけでPPOの学習を続けます（約200万ステップ、学習率1×10⁻⁴、30秒のエピソード）。
     設定値はノートブックの `CONFIG['specialist']` にあります。
   - 学習の乱数seedを5・6・7と変えて3回学習し、それぞれ約25万ステップごとに途中のモデルを保存します。
   - 保存した候補を検証の波30条件（0.10 m/s）で比べ、静止甲板で正しく歩けるもののうち完走が最も多いものを選びます。
     同梱のファイルは、seed 5の761,856ステップ時点のモデル（検証の波で30条件中21完走）です。
   - 著者はこの学習を、ノートブックと同じコードでCPU上で行いました。同梱にあたって、読み込みに必要な項目
     （重み、設定、ステップ数、seed、ネットワークの形、説明文）だけを残し、著者の環境のファイルパスは除いています。

学習（PPO）は、GPUの並列計算で足し算の順序が実行ごとに変わるため、同じ設定でも毎回少し違うモデルになります
（著者が低速専用モデルを3回学習したときの評価の完走は11・10・10）。
そのため、評価した組み合わせをそのまま再現できるよう、2つのモデルを同梱しています。
どちらもPythonのpickleファイルです。pickleは読み込むとコードを実行できるので、このリポジトリなど信頼できる入手元のものだけを使ってください。
v6のノートブックは読み込む前にSHA-256を確認します。

### 学習からやり直す場合
- **低速専用モデル**：v6のノートブックの設定セルで `TRAIN_SPECIALIST = True` にします（約1.5時間増）。学習の揺らぎにより、結果は同梱のモデルと一致しないことがあります。
- **v0のモデル**：`unitree_go1_multispeed.ipynb` を実行すると、上の `experiment04_multispeed/level_04/policy.pkl` に保存されます。
  同梱のファイルとSHA-256が違う場合、v6のノートブックは注意を表示して続行しますが、低速専用モデルは同梱のv0から学習したものなので、両方とも学習し直すことをお勧めします。

### v6の0.20・0.30 m/sの結果について
指令速度は1回の走行の間ずっと一定なので、0.20・0.30 m/sのv6はv0そのものです。そこで評価では、この速度の走行を2回計算せず、
同じ評価で走らせたv0の走行をそのままv6の結果とし、0.10 m/sだけ低速専用モデルで走らせて組み合わせます（`test_trained/joined.json` に記録）。
GPUは実行ごとに計算の方式や足し算の順序が変わることがあり、同じ制御器を2回走らせると、際どい条件の完走・転倒がわずかな差で入れ替わることがあるためです。
著者のColabでの最初の実行では、0.20 m/sのseed 1000で、v0は完走し、v6として走らせ直した同じv0のネットワークは11.6秒で転倒しました
（この条件はv0でも、開始位置を9通りずらすと完走は2通りだけです）。
GPUの計算を固定するXLAの設定（`--xla_gpu_deterministic_ops=true --xla_gpu_autotune_level=0`）も試しましたが、Colab L4では最初の1ステップで数値が発散したため使っていません。

### GPUがない場合
Linux（WSL2を含む）で、設定セルの `ALLOW_CPU = True` にすれば実行できます（評価だけで約2時間）。
CPUとGPUでは計算の細部が違うため、際どい条件では完走・転倒の結果が異なることがあります。

## 結果（Colab L4でノートブックの「すべてのセルを実行」をした結果）
| | 公開方策のみ（学習前） | v0 | **v6** |
|---|---|---|---|
| 評価15条件の完走 | 6 | 10 | **11** |
| 0.10 m/s（5条件） | 2 | 2 | **3** |
| 0.20・0.30 m/s（10条件） | 4 | 8 | 8（v0と同一） |
| 静止甲板15条件 | 15 | 15 | 15 |
| 検証の波（0.10 m/s、30条件） | － | 8 | **18** |
| 開始位置を9通りずらしたときの完走数の期待値（12条件、著者のCPU検証） | － | 9.22 | **10.22** |

- v0より悪化した条件はありません。0.20・0.30 m/sでは同じモデルを使うので、完走も速度追従もv0と同一です。
- 0.10 m/sで新たに完走したのはseed 1001です。seed 1000は転倒しましたが、転倒までの時間がv0の11.6秒から19.9秒に延びました。
- 0.10 m/sの揺れる甲板では、v6の速度誤差（RMSE、二乗平均平方根誤差）は0.137 m/s（v0は0.111 m/s）で、指令よりやや速く歩きます。
- seed 1003は約4.8秒で甲板が重力加速度より速く下へ動き、足が甲板から離れるため、どのモデルも完走できません（実質的な上限は12/15）。
- 評価15条件の完走・転倒の判定は、学習前・v0・v6の45件すべてで著者のCPU検証と一致しました。検証の波の完走数はCPUではv0 10、低速専用モデル 21で、GPUとCPUの計算の細部の違いにより少し異なります。
